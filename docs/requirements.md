# Spectra-bot 需求背景与前期调研记录

> 最后更新：2026-11-23
> 最新敲定的架构与模块设计以 [decisions.md](decisions.md) 为准。本文保留核心需求意图与前期技术调研参考。

## 总目标

做一个挂在 QQ（NapCat / OneBot v11）上、有“活人感”、有思考和学习能力、能像真人群友一样在群聊里自然聊天的独立 Agent（`Spectra-bot`）。

---

## 核心需求清单

1. **不同群聊、不同私聊支持独立 `sysprompt`**：面对不同群、不同人展现不同的状态，通过本地 `prompts/*.md` 管理基础人设。
2. **自进化（印象与相处方式演化）**：核心基础人设固定防崩坏；聊天内容通过后台固定 Workflow 更新“群聊画像”与“用户画像（含对该用户的印象与相处方式）”。
3. **双长期记忆库 + 按需召回**：
   - **通用/分群知识库**：记录聊天中学到的梗、黑话、术语、群规（如“区的意思是蛆”），抹除说话人身份信息，默认带群作用域与置信度防投毒。
   - **用户记忆库**：按 QQ 号跨群/私聊共享，包含结构化用户画像（整体重写覆盖旧矛盾）与具体事件记忆（标记来源为 `group` 或 `private`，群聊严禁召回私聊事件记忆）。
4. **记忆提取与归属判断**：后台异步从新增对话中提炼信息，由提取 LLM 一次性区分归入知识库、用户记忆库或丢弃，并配套整理与过期遗忘。
5. **基于 Jev 的读空气与动态 Effort 路由**：群聊闲聊经防抖与本地预筛后，单次调用 Jev 同时判断“是否接话”与“使用 `default` 还是 `high` effort”；私聊与被 `@` 消息直接调用 Jev 判断 effort。
6. **多 Session 隔离 + 记忆共享 + 临时 Subagent**：
   - 每个 QQ 群、每个私聊作为独立 `Session`（只追加日志 + 分块压缩投影，最大化命中 Prompt Cache）；
   - 遇到多步搜索或跨大量记录比对的重任务时，按需派生独立上下文的临时 `Subagent`，只将精炼结论返回聊天 Session。
7. **后期 / 暂缓需求**：
   - `no_reply` 主动沉默工具（推迟至后续版本）；
   - 日记系统（参考 DSH 日记插件：公开/私密分篇、先判是否值得写、顺带整理记忆，暂缓）；
   - 好感度系统（后期需求）；
   - 群聊无语义水屏动态规则库（暂缓）。

## 关键外部技术调研备忘

### 1. Jev（TypeSafe "System One" 决策模型）
- **定位**：托管决策模型，不生成自由文本，仅针对给定 `state` 与 `questions` 数组输出概率。
- **三种问法**：
  - `noul`（是/否）：返回为真的概率；
  - `choice`（多选一）：每个选项配描述，返回各选项概率与置信度（最多 255 项）；
  - `score`（打分）：2~10 个等级描述，返回加权分与各等级概率。
- **接口与成本**：`POST https://api.typesafe.ai/v1/systemone`（Python SDK：`typesafe-sdk`）；官方标称每百万输入 token 0.042 美元，输出免费；支持单次请求传入多个 `questions`。
- **已知注意点**：
  - `state` 中无关内容越少越准（只喂最近 8~10 条消息）；
  - 对选项顺序敏感，需固定顺序并用真实中文群聊样本标定阈值；
  - 计数、算术与日期推理较弱；需设置硬超时降级（800ms~1s）。

### 2. Apache Maka / OpenClaw / DSH 的多 Session 与上下文启示
- **Event Log + Projection（Apache Maka）**：SQLite 只追加记录不可变事件流，喂给模型的活跃上下文是日志的投影视图；避免逐条滑动窗口改写前缀导致大模型 KV Cache 失效，改为持续追加至阈值后再做分块压缩（Compaction）。
- **群聊记忆边界**：群聊 Session 默认禁止自动全量塞入私密记忆；轻量画像与字面命中的词条直接投影，深层历史记忆通过工具（如 `recall_memory`）按需拉取，在工具代码层硬隔离私聊隐私。
- **Session vs Subagent**：日常群聊/私聊窗口是 `Session`；`Subagent` 是遇到重度检索/推理任务时临时派生的干净上下文 Worker，只回传摘要防止污染聊天上下文。

### 3. 前期现有方案评估教训（避坑参考）
- **LivingMemory 的教训**：缺乏独立用户画像与去身份知识库拆分；只追加不覆盖矛盾；正则单字分类器误判严重影响有效期；默认无相关性门槛硬塞记忆污染上下文。
- **mem0（v3）的教训**：开源版改为只新增不覆盖；混合检索依赖英文 spaCy，中文退化为纯向量检索；提示词仅面向一对一聊天。
- **self_learning 黑话学习的借鉴**：“结合上下文猜词义 vs 只看词面猜词义”差异大则判定为黑话；注入时采用字面匹配命中才注入，避免无脑塞入。
